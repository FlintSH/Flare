# Uploading files

**Upload** is where files go up and come back as links. Drop, choose or paste them and they start at once, with the settings shown in the bar under the drop area, and each one appears below as a card like those in **Files**. Dropping or [pasting files onto any other dashboard page](./moving-around#paste-anywhere), or using a [screenshot tool](./screenshot-tools), uploads them with your saved settings, and each finished file opens its [sheet](./moving-around#a-sheet-for-every-file-and-link) when you click it.

## Upload from your browser

1. Open **Upload** and check the [options bar](#choose-the-options) under the drop area. Each button shows what the next files will get.
2. Add files: drop them anywhere on the page, choose **Choose files**, or copy files or a screenshot and press <kbd>Ctrl</kbd>+<kbd>V</kbd> (<kbd>⌘</kbd>+<kbd>V</kbd> on a Mac). On a phone or tablet, tap **Choose files**. Once files are listed, the drop area shrinks to a **Choose more files** line, and dropping or pasting anywhere on the page still works.
3. They upload right away, one at a time, each as a card below. When they finish, choose **Copy 3 links** (the count follows the files), or press <kbd>Ctrl</kbd>+<kbd>C</kbd> (<kbd>⌘</kbd>+<kbd>C</kbd>) with nothing selected, and paste the links where you need them.

Each file keeps the settings that were showing when you added it. Changing a button affects the files you add next, never a file that is already waiting or sending, so you can upload one batch as public and the next as private without waiting in between. Files you add while others are still uploading join their batch and wait their turn.

Each card shows the file's picture as soon as you add it (an icon and its extension for files that aren't images), dimmed until it has uploaded. While a file uploads, a bar runs along the bottom of its picture with the percentage beside it, and the card shows the bytes sent (and the speed, on wider screens); the line above the cards says which file of how many is going, the speed and about how long is left, and the browser tab's title starts with the percentage. Choose **×** on a waiting or uploading card to cancel it: nothing of it is kept, and Flare frees the parts of a large file it had already received. Once every byte has been sent the card shows a spinner and **Finishing…** while the server stores the file, and it can no longer be cancelled; delete it afterwards if you didn't want it. When a file arrives, its card shows the end of its link with a copy button, and icons on the picture for what it got: a lock when it is private, a key when it has a password and a clock when it expires. Hover over the link to see all of it.

A screenshot copied to the clipboard usually reaches the browser as `image.png`, so Flare names it by when you pasted it, for example `Pasted image 2026-11-22 09.05.07.png`. A copied file keeps its own name. Pressing <kbd>Ctrl</kbd>+<kbd>V</kbd> in a text field, an open menu or a dialog pastes there instead. Pasting text instead of a file offers **Make a paste**, which opens [Paste](./pastes) with the text, and pasting a single link offers **Shorten it**, which opens [Links](./short-links) with it filled in. Neither puts the text or link in the address bar.

The speed is measured over the last few seconds, appears about half a second after a file starts, and disappears once every byte has been sent. Earlier versions listed files first and uploaded them only when you chose **Upload 3 files**.

Uploading a ZIP, TAR, TAR.GZ/TGZ, or GZIP stores it as one file. It does not automatically extract or publish its members. Open **Browse archive** from its library menu to inspect it, or [extract into a new folder](./archives#extract-into-your-library). Archive browsing supports archives of any size, but an upload succeeding does not mean every entry can be previewed or the archive extracted; extraction has its own limits.

Anyone who can access a supported archive's [share page](./archives#browse-an-archive-shared-with-you) can browse and download its entries under the file's visibility/password rules. This does not create separate library files. Review the archive's contents before making it public.

## Choose the options

The bar under the drop area starts with your saved settings: your account defaults with your default [upload profile](./upload-profiles) on top. A button with nothing set, such as no profile, no folder or no tags, is drawn with a dashed outline and shows just its name (**Profile**, **Folder**, **Tags**); on a phone an empty **Folder** or **Tags** button shows only its icon. Change a button and it is highlighted with a dot, and its menu offers **Use saved setting** to go back. Your choices apply to every file you add until you change them again or leave the page. A file waiting its turn keeps its visibility, expiration and tags, even if you edit a profile, change your default profile or change your account defaults meanwhile: Flare sends them as they were when you added it. An expiration such as **After 1 day** still counts from when the file arrives. Random or original names and the share page style come from the profile when the file arrives.

| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Profile, such as **Screenshots** or **Profile**         | Which profile supplies the starting values. Each profile in the menu lists what it does: visibility, expiration, original or random names, tags and share page style. **No profile** uses your account settings only. **Make … the default** saves your pick as the default profile; **Manage profiles** (or **New profile…** before you have one) opens your profiles.                                 | `uploadProfiles.manage`                                                      |
| **Public** or **Private**                               | Who can open the files: anyone with the link, or only you. A public upload can also have a password; the button then reads **Public · password**.                                                                                                                                                                                                                                                       | `files.share`. Without it the bar shows **Private** and uploads are private. |
| Expiration, such as **Never expires**                   | **Never**, **After 1 hour**, **1 day**, **1 week** or **1 month** (counted from when each file arrives), or **Pick a date…** for a set date and time. Then choose **Delete it** or **Make it private**. The button names both, as in **Deleted after 1 day**. **Save as account default** keeps the choice for later uploads ([when it's offered](./moving-around#change-defaults-where-you-use-them)). | Everyone                                                                     |
| Folder, such as **Folder** (unfiled) or **Screenshots** | Which of your folders the files go into. **New folder…** creates one and selects it.                                                                                                                                                                                                                                                                                                                    | `folders.manage`                                                             |
| Tags, such as **Tags** (none) or **2 tags**             | Tags for the files. Your profile's tags start checked; changing the selection replaces them for this batch. **New tag…** or **Manage tags…** opens the tag manager.                                                                                                                                                                                                                                     | `tags.manage`                                                                |

A link to **Upload** can preselect a folder (`/dashboard/upload?folder=<id>`), as **Upload here** in **Files** does. Without `folders.manage`, the folder is ignored and uploads are unfiled. If the folder has since been deleted, the folder button reads **Folder unavailable**; it never moves the upload somewhere else on its own. Choosing a shared folder adds a line under the bar: public files there also appear on the folder's shared link.

When the options would make an upload fail (a password that breaks the rules, a deleted folder, or a profile that does something your role can't), the reason appears under the bar and files you add wait, marked **Not uploaded yet**, instead of uploading. Fix the option, then choose **Upload 2 files** above the cards.

Passwords apply to the files you add while one is set. They are never saved in upload profiles or exported recipes, the page forgets each file's copy once it has been sent, and a private upload ignores one. Flare accepts file passwords with at least 8 characters and at most 72 bytes; accented characters and emoji can use more than one byte each. A password that breaks the rule turns the button into **Check password**, and the reason appears under the bar.

If your default profile adds tags but your role can't apply tags (`tags.manage`), the page says so and holds files until you choose another profile. If you can't choose profiles, ask your administrator to change your role or default profile.

Earlier versions kept these settings in selects and a closed **Upload options** section, and had no tag choice. Until this version the buttons sat in a row above the drop area, empty ones read **No profile**, **Unfiled** and **No tags**, and on a phone the row scrolled sideways instead of wrapping.

## Set an expiration

An upload with a **Delete it** expiration requires `files.delete`; **Make it private** requires `files.share`. The menu disables an action your role can't use, and picking a time keeps an action it can. A role with neither can only choose **Never**. If your saved profile or account default expires files with an action your role can't use, the page says so under the options bar and holds files until you choose **Never** or the other action. To change it for good, update the profile or default, or ask the administrator for the permission.

The 1 hour to 1 month choices count from when each file arrives, so a file uploaded a minute after another expires a minute later. **Pick a date…** opens a dialog with shortcuts, a calendar and a time, and sets one moment for every file you add with it.

<Screenshot src="/screenshots/workspace/upload-expiration.png" alt="Expiration menu open on the Upload page, with Never, After 1 hour to After 1 month and Pick a date, and Delete it or Make it private below" caption="Choose when the files expire and what happens to them then." />

The server checks for due expirations every 5 seconds, so access changes a few seconds after the time you chose, not at that exact second. If an expiration can't be applied, for example while storage is unreachable, Flare tries again 1, 5 and 30 minutes later. If the last attempt also fails, the file stays as it is and **Files** stops showing its expiration; set it again from **Expires → Change** in the file's [sheet](./moving-around#a-sheet-for-every-file-and-link), where you can also change or remove an existing schedule.

## Quick drag-and-drop

When you drop files onto a dashboard page outside **Upload**, the overlay names what they'll get, for example **Public · Never expires · into Screenshots · Screenshots profile**, and uploads them with your default profile and account settings, without opening the Upload page. [Pasting files](./moving-around#paste-anywhere) on another page does the same after you press <kbd>Enter</kbd>.

If you are viewing a folder in **Files** and your role can organize folders (`folders.manage`), the dropped files go into that folder. Otherwise, and in **All files**, **Unfiled**, or other dashboard pages, they are unfiled. An active tag filter does not automatically tag new uploads: use a profile's tag selection or an automatic tag rule for that.

Dropped files join the same list as **Upload**, so they appear there with their links, and files dropped while others are still uploading wait their turn. The progress card in the notifications corner (bottom right, or the top on a phone-sized screen) shows the file being sent, and a notification with the links appears when the batch finishes; its **Manage** opens a single file's [sheet](./moving-around#a-sheet-for-every-file-and-link). If a file fails, the notification says why, how many others uploaded, and offers **Open Upload**, where you can retry it and copy the others' links. Earlier builds refused files dropped while another drop was still uploading, with **An upload is already in progress**.

## Use the finished links

**Copy** above the cards copies the links of the newest batch, one per line, and so does <kbd>Ctrl</kbd>+<kbd>C</kbd> (<kbd>⌘</kbd>+<kbd>C</kbd>) or **Edit → Copy** while nothing on the page is selected and no field, menu or dialog has focus. While some files in the batch are still uploading, the button says how many links are ready, as in **Copy 2 of 3 links**. Each card's copy button copies that file's link, and the card is outlined for a moment to show it was copied. On phones and tablets with a share sheet, **Share…** in the menu (**⋯**) next to **Copy** sends the links to another app.

The format half of the **Copy** button (**Link ▾**) chooses what it copies. Flare remembers the choice in this browser; where the browser won't store it, as in some private windows, the choice holds until you leave the page.

| Choice          | What is copied                                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Link**        | The share page, such as `https://files.example.com/alex/lake.jpg`. Chat apps show its [preview](./embeds).                                                                |
| **Direct link** | The file itself, the share page's address with `/raw` added, for embedding in a forum post or another site.                                                               |
| **Markdown**    | `![lake.jpg](https://files.example.com/alex/lake.jpg/raw)` for an image, so it shows in a README or issue; `[report.pdf](…)` linking to the share page for anything else. |

A card's menu (**⋯** on its picture) offers the other formats for that file, **Open**, and the settings the file got. Copied links never include a file password: a direct link or Markdown image of a private or password-protected file opens only for you. Screenshot tools keep copying the share page, as their [configurations](./screenshot-tools) say.

If a file went up public by mistake, choose **Make private** in its menu, or **Make 3 private** in the menu (**⋯**) next to **Copy** for the batch; it needs `files.share`. **Delete…** in a card's menu deletes the file after you confirm, with `files.delete`; its link stops working for everyone.

The newest batch stays at the top. Earlier batches move under **Earlier · 4 files**, closed until you open it, with the same cards, links and menus. The list lives as long as the browser tab: go to **Files** and back and your links are still there, and uploads carry on meanwhile. Reloading or closing the tab ends it, and the browser asks first while files are still waiting or uploading. Only the latest 100 finished files are kept, and signing in as another account clears it. **Clear list**, next to **Copy** (in the **⋯** menu on a phone), removes finished files from the page; they stay uploaded in **Files**. Files and links are kept in the tab's memory only, never in browser storage.

The link ends in a URL-friendly version of the filename: `My Report.PDF` is shared as `my-report.pdf`, and the file keeps its original name everywhere else in Flare. Uploading another file with a name you've already used gives the new file its own link with a short random suffix, such as `my-report-3f9c2a71-b04.pdf`; the earlier link doesn't change. A filename with no A to Z letters or digits, such as `日本語.png`, gets a short random link name instead. Choose random names in an [upload profile](./upload-profiles) if you'd rather not show filenames in links at all. The [file API guide](/api/files#upload-one-file) lists the exact rules.

If the browser refuses clipboard access, open the file and copy the address from there.

## Tips on an empty Upload page

Until you hide them, an empty Upload page shows a line of tips at the foot of the drop area, on screens wider than a phone:

- **Upload from ShareX, Flameshot and other tools: set one up** opens the downloads for [ShareX, iTake, Flameshot, Spectacle and the Bash script](./screenshot-tools), which upload with your saved settings, including your default profile once you choose one. It shows while your role has `files.upload` and `tokens.manage`.
- **Save settings you reuse as a profile** opens **Profile → Uploads** at your [profiles](./upload-profiles). It shows while your role has `uploadProfiles.manage` and you haven't saved a profile yet.

<Screenshot src="/screenshots/workspace/upload-tips.png" alt="Upload page for a new account: the drop area with Choose files, and under it one line of tips with set one up and as a profile links and a close button, above the options bar" caption="A new account’s Upload page. The tips step aside while files are listed." />

The tips step aside while files are listed and come back when the list is empty. Earlier versions showed them as a separate box of two tips under the drop area, on phones too. Choose **×** (**Hide these tips**) to hide them for good. Flare saves that on your account, so they stay hidden on your other devices too. If the choice can't be saved, the tips stay and Flare says so; try again. Nothing brings them back once hidden: profiles and the tools stay under **Profile → Uploads**.

## Size limits and larger files

The drop area shows the maximum allowed file size. A larger file isn't added, and the page says how many weren't. Your account may also have a total storage quota, visible under **Profile → Your data**. A file can fit the per-file limit and still exceed your remaining quota. A file over either limit is refused as a whole: Flare shows **A file exceeds the upload size limit.** or **This would exceed your storage quota.**, and none of the file is saved or counted against your quota. Uploads that finish at the same time are checked one after another against your remaining quota, so together they can't go over it. Extracting or creating an [archive](./archives) applies the same limits with the same messages. Earlier versions worded these refusals six ways, for example **You have reached your storage quota.** or **The output files would exceed your storage quota.**

The browser automatically uses chunked transfers for files larger than 10 MiB. You do not need to split files yourself. Keep the tab open: this uploader does not offer a resume-after-browser-restart interface.

File types may be restricted by the administrator, and the server checks file contents as well as the reported type. Renaming a blocked file's extension does not make it an allowed file.

An administrator with `audit.read` can investigate [Audit log](/admin/audit) using the filename, account, time, and available request context. Upload/finalization records retain the file ID and name when the server can identify them, including useful context for some failures; they do not contain file bytes or submitted passwords. An early proxy rejection or interrupted request may not reach Flare at all, so provide the visible error and approximate time rather than assuming every failed transfer has an audit event. OCR and later background work have separate outcomes after upload acceptance. An image OCR can't read is marked as read with no text, and an `ocr.failed` event records it. Earlier versions also left a text-recognition worker running for each such image until Flare restarted, so many unreadable images could slowly use up the server's memory.

## If Upload is missing or refuses

Uploading requires `files.upload`, including drag-and-drop, screenshot tools, and chunked uploads. Role changes apply on the next request; an existing upload credential cannot bypass them. Revoking a [named API token](/api/authentication#rotate-or-revoke-a-token), or reaching its expiry, also stops an upload it is still sending: when the file has arrived, Flare refuses it and keeps none of it. Sharing changes use `files.share`. Without that permission, new uploads are private even if a profile or request selected public visibility; you can still upload when `files.upload` is granted. Existing public links stay public until explicitly changed. If Upload is unavailable, ask the instance administrator to review your [roles](/admin/roles).
